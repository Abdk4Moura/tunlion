## A. Web shell — EXPERIMENTAL, moved to backlog (2026-06-15)
> Status: the redesign (font sizing, symbol drawer, status pill, command mode)
> shipped behind the harness but the feature as a whole is still too buggy to
> promote. Declared **experimental** and parked at the back of the queue. Active
> focus is now the consolidation refactor — see `consolidation-plan-2026-06-15.md`.

The incremental fixes landed (IME corruption, touch scroll, freeze + auto-recover,
mobile viewport fit, persistence, predictive echo, truecolor). But a raw desktop
terminal is inherently awkward on a phone; the ceiling is low. Proposed redesign,
keep xterm.js as the rendering core (TUI correctness) but build a real mobile UI:

1. **Layout**: true full-screen, readable default font with +/- and pinch, the
   input row + accessory bar ALWAYS pinned above the soft keyboard.
2. **Accessory key bar (the big one)**: Esc, Tab, sticky Ctrl/Alt, arrows,
   Home/End, PgUp/PgDn, and common symbols (| / ~ - * " ' etc.), customizable.
3. **Two modes**: full-terminal mode for TUIs (vim/opencode), and a "command
   mode" for normal use, a clean input field with history + autocomplete and a
   scrollable output pane (most phone use is run-a-command, not a live TUI).
4. **Interaction**: the scrollbar + gestures, big copy/paste, a reconnect/status
   pill, haptics.
Phase it: ergonomics + layout first, command-mode second. Decision needed: keep
xterm core (recommended) vs a heavier rewrite. Tell me which ergonomics matter
most (re-pick from the list I sent earlier if any changed).
